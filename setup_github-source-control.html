Github Source Control

Overview

When we edit code, we save versions as we go though special software. This is called source control software (source means source code). The most common source control software today is called Git.

When multiple people want to edit the same code, we can not longer just store it on our local machine. There are online providers that host Git. You can publish your code for anyone to look at and contribute to. The most popular service is called GitHub and it is free for non-commercial use.

Create an Account

Go to https://github.com/ and sign up for an account.

When choosing a username, pick something professional. People have there GitHub accounts for many years and even decades. You can always create another account, but it is better to just pick a username you can live with in the beginning. Every code change you make will be stamped with this user name.

How to Use

There are plenty of resoruces online, like https://github.com/git-guides.

Here are some basics though:

  • Let's assume that a project already exists (online in GitHub)
  • First, you clone the repository to your local machine.
  • Then, you open it up in your editor.
  • You could just start editing code, but normally we create a branch. This allows many people to make independent changes and then safely merge them into the main branch without breaking everything.
  • When are done editing and testing your code locally, you save a version in Git by issuing a commit. You can commit as many times as you want while working on a feature.
  • When you ready to let others look at it, you push your local changes to the remote server (GitHub).
  • To tell others to look at it, you create a pull request. You want them to pull your changes into the main branch.
  • But we don't just do that without looking at it. Others review your code, ask questions, and make suggestions. This is what gets us to a higher quality codebase.
  • From all those comments, you will likely edit your code, commit, push, and repeat the process.
  • When all items are resolved, the repository maintainer will merge into the main branch.
  • The maintainer will usually delete your branch on GitHub, and you may need to delete the branch on your local machine.
  • When you are done with your project, you can just delete the local copy (but many will leave it).
Whew! That sounds like a lot, but it becomes second-nature after awhile.
